# Cadence — Demo Voice-Over Script

**Format:** Side-by-side demo — Desktop app (left) + Web app (right)
**Target length:** ~5–7 minutes
**Tone:** Conversational, confident. Speak like you're showing a friend something you built, not reading slides.
**Voice-over:** Generated with [ElevenLabs](https://elevenlabs.io) — see ElevenLabs setup notes at the bottom.

---

## INTRO (0:00 – 0:30)

> "Hey — this is Cadence. It's an AI-powered pronunciation training app for non-native English speakers.
>
> Most tools give you a score after you speak. Cadence goes one level deeper: it tells you which exact sound is off, and hands you straight back to the microphone with a cue to fix it.
>
> We built it as two products that share one codebase — a desktop app that runs entirely offline using local AI models, and a web app that connects to a cloud backend with Supabase auth and Stripe billing.
>
> Let's walk through both."

## PART 3 — LEARN: STRUCTURED MODULES (1:50 – 2:40)

*[Navigate to `/learn`]*

> "The Learn section is the structured curriculum. Each card is a pronunciation module — vowel sounds, consonant clusters, stress patterns. Each module has three lesson types: Theory, Practice, and Exam.
>
> Theory lessons have narration — there's a text-to-speech button that plays a reference audio of the target word, generated by the local OmniVoice model or the cloud TTS depending on your mode."

*[Open a Practice lesson — show PracticeStudio]*

> "This is the Practice Studio. The target word is displayed with its IPA phonemes. You hit record, speak once, and Cadence sends the audio through the pronunciation scoring engine — a PyTorch model running on FastAPI.
>
> The result comes back with an overall score out of 100, a progress bar, the transcribed phonemes versus the target, and then these color-coded chips — green means you nailed that sound, yellow is close, red is the one to work on.
>
> Below that is a grid of individual phoneme cards. Each one shows the symbol, what was expected, what was heard, and an accuracy percentage. At the bottom: a 'Next repetition cue' — a specific instruction like 'focus on the final consonant cluster, try again with a slightly shorter vowel.'
>
> That's the core feedback loop: speak → see the exact phoneme that's off → get a cue → go again."

In cloud mode there's a cancel subscription button wired to Stripe. In desktop local mode you get an info panel showing the runtime version and model paths."

---

## PART 8 — TECH STACK & DESIGN CHOICES (5:00 – 6:00)

> "A few things worth calling out on the technical side.
>
> The frontend is Next.js 16 App Router with React 19 and Tailwind CSS 4. All pages are server components — they fetch data on the server, no loading spinners on the client. The API routes under `/api/` are a typed proxy layer. The browser never calls the Python services directly; everything goes through Next.js, which resolves the right backend URL based on whether you're on web or desktop.
>
> The two Python backends are FastAPI. The AI engine handles pronunciation scoring using a fine-tuned phoneme model, transcription using Whisper, and TTS using OmniVoice. The coach engine runs the Qwen LLM for conversation turn generation.
>
> For data, cloud mode uses Supabase — standard PostgreSQL with row-level security. Local mode stores progress in an httpOnly cookie as compact JSON and uses localStorage for session history. Both modes share the same data-access interfaces, so the UI never knows which backend it's talking to.
>
> The desktop app is Electron wrapping the Next.js standalone build. The setup manager handles downloading models, starting services, and polling health — it stores a setup manifest so on subsequent launches it just starts, it doesn't re-download anything.
>
> Deployment: the web app is on Vercel. The Python backends can run in Docker on any container host. There's a `docker-compose.yml` for local self-hosting."

## Screen-Recording Tips

- Start on the landing page (`/`) before cutting to the demo — shows the product is public-facing.
- Use a split-screen: Desktop app window on the left, browser (web app) on the right.
- Record at 1440p or 1080p; the card grid layouts look best at full width.
- Mute system audio during recording; add the voiceover in post.
- For the Practice Studio section, pre-record a clean take of the target word so the phoneme feedback is visible — don't rely on live microphone input during screen capture.

## ElevenLabs Voice-Over Setup

### How to generate the audio

1. Go to [elevenlabs.io](https://elevenlabs.io) → **Text to Speech** (or **Projects** for multi-segment work).
2. Paste each section's quoted text — the lines between `> "` and `"` only. Strip the stage directions (lines in `*[italics]*`) before pasting.
3. Recommended voice settings:
   - **Voice:** Adam, Josh, or Charlie — all land in a neutral, confident register that fits a product demo
   - **Model:** `eleven_multilingual_v2` (best quality) or `eleven_turbo_v2_5` (faster, cheaper, still good)
   - **Stability:** 0.55–0.65 — keeps delivery natural without too much variation
   - **Similarity:** 0.75 — clean reproduction of the chosen voice
   - **Style:** 0.20 — slight expressiveness without sounding overdone
   - **Speaker Boost:** on

### Workflow for a multi-section demo

Use **ElevenLabs Projects** (the long-form audio editor) rather than pasting the whole script as one block:

1. Create a new Project and paste the full script text.
2. The editor breaks it into paragraphs automatically.
3. Delete or mute any paragraph that is a stage direction.
4. Assign the same voice to all paragraphs and hit **Generate All**.
5. Export as a single WAV or MP3.

This keeps the pacing consistent across sections without needing to manually stitch clips.

### Syncing audio to the screen recording

- Export the ElevenLabs audio first, then record your screen while listening to it on headphones — this lets you time your mouse movements to the narration.
- Or record the screen first and trim/stretch clips in your editor (CapCut, DaVinci Resolve, iMovie) to match the audio.
- The timing guide above is calibrated to the script length — each section's duration matches roughly how many words are spoken at a normal demo pace (~140 wpm).
